## 0. الخلاصة التنفيذية

**طبيعة النظام:** تصنيع حسب الطلب مبني على **العقد** (عرض سعر → عقد بأقساط → أمر تصنيع لكل صنف/سيريال → مراحل ورشة → تشطيب → تسليم وتركيب بمقاولين أو فرق داخلية → استلام نهائي). ده نموذج قوي ومناسب لمصنع معدات بيركّب عند العميل، وفيه حاجات مش موجودة في Warsha: تتبع مصدر المخزون بالسيريال، مقاولي التركيب بنسب وأقساط، مأموريات ميدانية بتكلفة على بند العقد، بصمة وحضور ورواتب متقدمة، WIP للعقود، تطبيق أندرويد شغال.

**أخطر 5 مشاكل:**
1. **لا يوجد فاتورة إلكترونية ETA ولا إيصال إلكتروني ولا خصم وإضافة** ✅ — الفواتير غير صالحة قانونياً في مصر. (Warsha عنده ETA جاهز — يمكن نقله.)
2. **الضريبة والخصم وسعر التكلفة تُؤخذ من العميل (client) كما هي** ✅ (`ManufacturingRepository.SalesInvoices.cs:2077-2104`) — أي مستخدم يقدر يسجل ضريبة خاطئة أو خصم بلا حد أو تكلفة مزيفة.
3. **أرصدة المخزون "بتنحرف" بالتصميم** — مفيش ledger واحد؛ 3 طرق مختلفة تكتب الرصيد، ومعامل الوحدات يتقرّب لخانتين في مكان و6 في مكان ✅ (`SalesInvoiceEntries.cs:1219` مقابل `StockMovements.cs:2488`). أدوات Fix/Reset موجودة كعَرَض للمرض، وهي نفسها تعدّل الكمية بدون حركة أو قيد.
4. **الإيراد يُسجّل كاملاً عند توقيع العقد** (`Contracts.cs:3635-3745`) — مخالف لمعيار المحاسبة المصري 48، واحتمال **إيراد تركيب مكرر** عند الاستلام النهائي.
5. **الاتصال HTTP بدون تشفير** (`appsettings.json:10,13`، أندرويد `usesCleartextTraffic=true`) + تجديد جلسة الجهاز بلا انتهاء (`AuthController.cs:57`) — كلمات السر والتوكنات تمر مكشوفة على الإنترنت، والتوكن المسرّب يتجدد للأبد.

## 4. خارطة طريق مقترحة

**الموجة 0 — أمان وصحة الأرقام (2–3 أسابيع):** HTTPS إجباري وتخزين مشفر للتوكن (S1, S7)، إصلاح تجديد الجلسة (S2)، إعادة حساب الضريبة والخصم والتكلفة على السيرفر (S3)، صلاحيات الـ endpoints والـ IDOR (S4–S6)، state machine للمراحل، توحيد معامل الوحدات + منع تعديل وحدات صنف له حركات (I1, I2)، الإضافي والإجازة المدفوعة (H1, H2)، قفل سطر العقد وصيغة المتبقي (P1)، إزالة `catch {}` الصامتة (A9)، `decimal` بدل `double` في القيود.

**الموجة 1 — امتثال وأساسيات (P0):** ETA B2B (نقل من Warsha) + خصم وإضافة + تأمينات وكسب عمل وقيد رواتب بالإجمالي، إقفال الفترات، الاعتراف بالإيراد عند التسليم وحل الإيراد المكرر، Ledger مخزون موحد يلغي أدوات Fix/Reset، أوامر شراء واستلام، تطبيق الفني الميداني، نقل الأندرويد للمسار الجديد.

**الموجة 2 — ما يتوقعه السوق (P1):** ربحية العقد، أصول ثابتة، تسوية بنكية، أعمار الذمم، مستخلصات، حد ائتمان وقوائم أسعار، تذاكر صيانة وضمان بالسيريال، فحص جودة، تحميل عمالة/overhead على الأوامر، MRP زمني، اختبارات آلية + migrations بإصدارات، تحديث تلقائي للديسكتوب، باركود وإشعارات ولوحة المالك.

**الموجة 3:** إيصال إلكتروني B2C، routing وجدولة، صيانة ماكينات وOEE، WhatsApp API، عملات أجنبية، إعادة هيكلة الديسكتوب لـ MVVM.
